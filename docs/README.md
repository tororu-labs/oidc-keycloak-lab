# docs ディレクトリ運用メモ

`docs/` は、再現したい手順や、あとから安定して参照したい内容を置くためのディレクトリである。  
このリポジトリでは、学習用のセットアップ手順、再現手順、構成整理、参照用の設計メモを `docs/` にまとめる。

一方で `notes/` は、学習メモ、試行錯誤、レビュー整理、理解途中の考察を残すためのディレクトリとして使う。  
つまり、`docs/` は「学習用だが、あとから読み返して再現しやすい形に整えた文書」、`notes/` は「学習途中の記録や整理メモ」という役割分担にする。

------

## 使い分け

### `docs/` に入れるもの

- 再現したいセットアップ手順
- 学習用の再現手順
- 必要に応じた運用手順や runbook
- 構成整理や参照用の設計文書
- 後から見ても迷わない形に整えた記録

### `notes/` に入れるもの

- 学習メモ
- 調査中の途中記録
- 問題調査やレビューの整理
- まだ結論が固まっていない考察

------

## 命名ルール

新規の `docs` ファイルは、原則として以下の形式で命名する。

`NN_<Category><Topic>.md`

- `NN`
  - 2 桁の表示順
  - 例: `00`, `01`, `10`
- `Category`
  - 文書の種類を表す英語識別子
  - 例: `Setup`, `Runbook`, `Architecture`
- `Topic`
  - 扱う対象やテーマを表す識別子
  - 例: `Docker-Keycloak`, `RotateClientSecret`, `AuthFlow`

ファイル名の例:

- `00_SetupDocker-Keycloak.md`
- `01_RunbookRotateClientSecret.md`
- `10_ArchitectureAuthFlow.md`

文書の中の見出しや本文は日本語で記述してよい。  
既存ファイルは今回は命名変更せず、今後新しく作る `docs` から徐々にそろえていく。

## テンプレートの使い方

新規の `docs` を作るときは、まず [`_TEMPLATE.md`](./_TEMPLATE.md) をコピーして使う。

基本方針:

- まずテンプレートを複製し、ファイル名を `NN_<Category><Topic>.md` 形式に変更する
- 冒頭の HTML コメントを読み、不要な章を削除する
- 文体は既存の `00_Setup...` と同じく、記録文と箇条書きを組み合わせて書く
- 区切り線は `------`、コードブロックは `~~~` を使う
- 見出しは重複させず、`### Realm 作成の補足` のように章名を含めて書く

------

## 文書タイプごとの使い方

### 手順書として使う場合

以下の章を残すことを推奨する。

- `## 前提確認` または `## 前提条件`
- `## 実施概要`
- `## 完了判定`

GUI 操作が中心の文書では、`## 実行コマンド一覧` は削除するか、前提確認用のコマンドだけを残してよい。

必要に応じて、各主要セクションの中に `### [章名] の補足`、`### [章名] 完了時の状態`、`### [章名] の判定` を残す。

### 構成整理・設計文書として使う場合

以下の章を活かすと整理しやすい。

- `## 背景`
- `## 関連ドキュメント`

この用途では、`## 本ドキュメントで完了したこと`、`## 実行コマンド一覧`、`## 完了判定` などの手順書向け章は削除してよい。

------

## 補足

- `docs/` は参照用の整った文書を置く場所とし、途中経過だけのメモは `notes/` に寄せる
- 既存文書を一括でテンプレートへ合わせる必要はなく、新規作成時からそろえていく
- テンプレートは `Setup` 系を基準にしているが、不要章を削れば他の `docs` にも流用できる
- 文体は「学習用だが再現しやすい手順書」を基本とし、概念説明は短く、実施手順は具体的に書く
